# 방카톡 — 보호자 문의·글 아래 질문 + 운영시간 (동래방카 요청 2·4·10번)

> 2026-10-28 설계. 요청 원문: 동래방카 저장소 `docs/REQUESTS_조유경_20261027.md` 2·4·10번.
> DB 변경: `supabase/migrations/bk_talk.sql` (확정, 실행은 관장님 MCP). 11장 결정 반영(2026-10-28).

## 0. 확정된 결정(관장)

- 2번(댓글)과 4번(방카톡)을 **같은 표**로. 공지·알림장·수업기록 아래 "질문하기"(그 글에 연결) + 방카톡 메뉴(연결 없는 일반 문의)
- 보호자 글은 **본인과 직원만** 봄(다른 보호자에게 안 보임)
- 직원 답글은 **담당 선생님 이름**으로 표시. 답글은 방카 담당 직무(bangka) 보유자 누구나
- 10번: 보호자 작성은 **평일 13:00~20:00(KST)**만, 주말·공휴일 막음. 운영시간 밖엔 안내 문구 + 공결 신청 링크 +
  센터 전화번호. 관리 화면에서 시각·요일 변경. **직원 답글은 시간 제한 없음**
- 직원 알림: 동업자씨 방카 메뉴에 **미답변 수 배지**. 슬랙은 업무시간에만(제안 4장)
- 보호자 알림: 앱 홈에 **"새 답글 N건"**(문자 연동은 나중)

## 1. 지금 구조에서 가져다 쓰는 것 (운영 DB·코드 실측)

- 방카 표(`bk_*`)는 모두 RLS 켜짐 + 정책 없음 → 두 앱 서버(service_role)만 읽고 씀. 방카톡도 같은 방식.
- 글: `bk_posts`(post_type = notice 공지 · class_note 알림장 · monthly_plan), 읽음: `bk_post_reads(post_id, guardian_id)`.
- 수업기록: `bk_class_sessions` 는 **뷰**(`saem_sessions` + 프로그램). 질문은 `saem_sessions.id` 에 연결.
- 보호자: `bk_guardians`(운영 4명) ↔ `bk_guardian_students` ↔ `bk_students`. 방카 직무 보유자 3명.
- 공휴일: 동업자씨 `lib/koreanHolidays.ts`(2026·2027 확정 표, 대체공휴일 포함, 순수 모듈).
- 센터 전화: 설정 `settings.organization_phone` = 051-988-0924.
- 슬랙: 동업자씨 `lib/slack.ts`(`sendSlack(webhookEnvKey)`), 사진: `bangka-media` 비공개 버킷.
- 동래방카 하단 탭에 "방카톡"(`/talk`)이 이미 있으나 빈 화면.

## 2. 표 구조 (SQL 1~4)

| 표 | 하는 일 | 핵심 칸 |
|---|---|---|
| `bk_talk_threads` | 대화 = 보호자 한 명의 문의 한 건 | `guardian_id`(주인), `student_id`(선택), `topic_type`(general·post·session), `post_id`·`session_id`, `topic_title`(제목 스냅숏), `status`(open·answered·closed), `last_message_at`·`last_guardian_at`·`last_staff_at`, `guardian_read_at`, `deleted_at` |
| `bk_talk_messages` | 대화 안의 말(첫 질문·추가 글·직원 답글) | `author_type`(guardian·staff), `guardian_id` / `staff_driver_id`·`staff_name`, `body`(1~2000자), `edited_at`, `deleted_at`, `hidden_at`·`hidden_by`·`hidden_reason` |
| `bk_talk_files` | 말에 붙은 사진(선택) | `message_id`, `path`(`talk/{thread_id}/…`), 크기·가로세로 |
| `bk_talk_settings` | 운영시간(한 줄) | `weekdays`(0=일…6=토), `open_time` 13:00, `close_time` 20:00, `block_holidays`, `extra_closed_dates`, `closed_notice` |

- **읽음 여부**: 보호자 쪽은 대화별 `guardian_read_at` 하나로 충분 — 대화를 열면 지금 시각으로 갱신,
  "새 답글" = `last_staff_at > guardian_read_at`. 직원 쪽은 사람별 읽음 대신 **대화 상태**로:
  `open` = 보호자 글이 마지막(미답변) → 배지 숫자. 직원 누구든 답하면 `answered`.
- 상태·시각은 **DB 트리거**(SQL 6)가 말이 들어올 때 갱신 — 두 앱이 같은 규칙을 따로 짜지 않음.
- DB 가 직접 막는 규칙: 보호자 글은 자기 대화에만, **닫힌 대화에는 보호자 글 불가**("닫힌 문의입니다", SQL 7),
  **사진은 말 하나에 최대 3장**(SQL 8). 직원 답글은 닫힌 대화에도 가능(닫으면서 마지막 안내).
- 질문이 글에 붙어 있어도 대화는 보호자별로 따로 — 같은 공지에 보호자 셋이 물으면 대화 셋(서로 안 보임).

## 3. 운영시간(10번)

- 저장: `bk_talk_settings` 한 줄(id=1). 기본 평일(월~금) 13:00 이상 ~ 20:00 미만, 공휴일 막기 켬.
- 판단(보호자 앱 서버, 한국 시간): 오늘 요일 ∈ `weekdays` 이고, 공휴일 아님, `extra_closed_dates` 아님,
  `open_time ≤ 지금 < close_time` 이면 작성 가능.
- **공휴일 목록 — 제안: 코드의 확정 표**(동업자씨 `lib/koreanHolidays.ts` 를 동래방카에도 같은 내용으로 둠)
  - 장점: 외부 API·키 불필요, 대체공휴일까지 사람이 검토한 표, 이미 연차·급여 계산에서 씀.
  - 단점: 해마다(지금 2027년까지) 표를 추가해야 함 → 표 끝 해(2027년) 12월에 동업자씨 첫 화면/관리 화면에
    "내년 공휴일 표를 넣어 주세요" 알림을 띄우는 것까지 제안.
  - 임시공휴일·센터 휴무일은 관리 화면의 **"추가로 막을 날"**(`extra_closed_dates`)로 그때그때.
  - 대안: 공공데이터포털 "특일 정보" API(키 발급·장애 시 판단 불가) — 권하지 않음.
- 막히는 것: 새 대화, 대화에 추가 글, 글 수정. **막히지 않는 것**: 읽기, 자기 글 지우기, 공결 신청, 직원 답글.
- 운영시간 밖 화면: 쓰기 칸 대신 안내 상자 — `closed_notice` + [공결 신청하기](`/more/absence/new`) +
  [센터에 전화하기 051-988-0924](`tel:`, 번호는 `settings.organization_phone` 에서) + "다음 운영: 월요일 오후 1시".
- 서버가 막음(화면만 막지 않음): 보호자 글 쓰는 API 는 진입하자마자 운영시간을 다시 봄. 창을 열어 둔 채
  20:00 이 지나 보내도 거절("방금 운영시간이 끝났습니다…", 쓴 내용은 화면에 남김).

## 5. 화면 흐름

### 보호자(동래방카)
- **공지·알림장 상세** `/ieum/{id}` 맨 아래: [이 글에 질문하기] → 새 문의(이 글 연결). 이미 이 글에 물은 게 있으면
  "내 질문 1건 · 답변 완료" 줄(누르면 그 대화). 다른 보호자 질문은 개수도 안 보임.
- **수업기록**(`/ieum?tab=log`) 각 기록 아래: [질문하기] → 새 문의(그 수업 연결).
- **방카톡 탭** `/talk`: 내 대화 목록(최근 순). 한 줄 = 연결된 글 제목 또는 "일반 문의", 마지막 말 한 줄,
  배지(새 답글 / 답변 기다림 / 닫힘). 아래 고정 버튼 [새 문의 쓰기](운영시간 밖이면 안내 상자).
- **새 문의** `/talk/new[?post=…|session=…]`: 자녀가 둘 이상이면 자녀 고르기(선택), 내용(2000자), 사진(선택), [보내기].
- **대화** `/talk/{id}`: 말풍선(보호자 오른쪽, 선생님 왼쪽 "조유경 선생님"), 아래 입력 칸(운영시간·닫힘이면 안내).
  열면 읽음 처리.
- **홈**: "새 답글 N건".

### 직원(동업자씨 `/bangka/talk`)
- 묶음: **미답변**(기본) / 전체 / 닫힘. 반(이음·지음) 거르기. 한 줄 = 보호자 이름·자녀·연결 글, 마지막 말, 기다린 시간.
  미답변이 **다음 운영일 끝까지** 답이 없으면 빨갛게(공결 증빙 3일 강조와 같은 모양, 기준은 결정 필요).
- 대화 화면: 말 전체(가린 글은 사유와 함께 회색), 답글 칸(시간 제한 없음, 이름 = 로그인 직원), 버튼 [가리기] [대화 닫기/다시 열기].
- **운영시간 설정**(`/bangka/talk/settings`): 요일 체크, 시작·끝 시각, 공휴일 막기, 추가로 막을 날, 안내 문구,
  미리보기("지금은 작성 가능/불가"). 바꿀 수 있는 사람: 관장·부장·방카 팀장(공결 결재권과 같은 기준).
- 글 관리 화면(공지·알림장 목록)에 그 글에 달린 질문 수 표시 → 누르면 그 대화들.

## 6. 보안 — 보호자는 다른 보호자 글을 절대 못 봄

1. **DB**: 네 표 모두 RLS 켜고 정책 없음 + anon·authenticated 권한 회수(SQL 5). 브라우저에 있는 키로는 어떤 줄도 못 읽음.
2. **보호자 앱 서버 — 한 곳에서만 읽기**: `lib/talkData.ts` 의 함수만 방카톡 표를 읽고, 모든 함수가
   `guardian_id = 로그인 보호자 id` 를 **쿼리 조건에 넣음**(읽은 뒤 거르는 방식 아님).
   - 대화 하나 열기: `id = ? and guardian_id = 나` 로 찾아 없으면 404(남의 대화인지도 알려 주지 않음).
   - 말·사진은 위에서 찾은 대화 id 로만 읽음. 사진 서명 URL(1시간)도 그 확인 뒤에만 발급.
   - 글 연결 질문 개수·목록도 `guardian_id = 나` 조건 안에서만.
   - 직원 이름 외에 다른 보호자 정보는 응답에 넣을 칸 자체가 없음.
3. **쓰기**: 보호자 글은 자기 대화에만 — 서버 확인 + DB 트리거(SQL 7)가 한 번 더(다른 보호자 대화에 붙이기 불가).
4. **세션**: 지금 로그인(`currentParent`)의 보호자 id 만 믿음. 요청 본문의 guardian_id 는 받지 않음.
5. **시험**: 휴대폰 점검 가짜 데이터에 다른 보호자 대화를 넣고, 그 id 로 열기·글쓰기·사진 열기가 모두 404 인지 확인하는
   검사를 추가.

## 7. 사진 첨부 — 확정: 표·규칙만 지금, 화면은 다음 배포

- 보호자·직원 모두 말 하나에 **사진 최대 3장**(이미지만, 긴 변 1600px 로 줄여 올림 — 공결 신청과 같은 방식),
  `bangka-media` 비공개 버킷 `talk/{대화 id}/…`, 보기는 1시간 서명 URL.
- 이유: "준비물 사진이 이게 맞나요?" 같은 문의가 많을 것. PDF·동영상은 받지 않음(필요하면 공결·센터 전화로).
- **첫 배포에는 화면 없음**(관장 결정). 표(`bk_talk_files`)와 "말 하나에 최대 3장" DB 규칙은 미리 만들어 둠.

## 8. 수정·삭제 규칙

- **보호자**
  - 자기 말 **수정**: 그 뒤에 선생님 답글이 없을 때만 + 운영시간 안. 고치면 "수정됨".
  - 자기 말 **삭제**: 그 뒤에 선생님 답글이 없을 때만(시간 제한 없음). 내용 대신 "삭제된 글입니다".
    대화의 첫 말을 지우고 다른 말이 없으면 대화째 숨김(`deleted_at`).
  - 선생님이 답한 뒤에는 수정·삭제 불가(기록 보존) — "고칠 내용은 이어서 적어 주세요".
- **직원**: 자기 답글 수정·삭제 언제든("수정됨"/"삭제된 답글"). 다른 직원 답글은 못 고침(관장·부장 예외는 결정 필요).
- 지운 글도 DB 에는 남김(소프트 삭제) — 분쟁 시 확인용. 영구 삭제는 보호자 계정 삭제(연쇄 삭제) 때만.

## 9. 부적절한 글 처리

- 직원 **[가리기]**(사유 필수): 그 말의 내용을 보호자 화면에서도 "선생님이 가린 글입니다(사유)"로 바꿈. 직원 화면엔 원문 + 사유.
- **[대화 닫기]**: 더 이상 보호자가 그 대화에 쓸 수 없음(새 대화는 가능). 다시 열 수 있음.
- 반복되는 경우의 **보호자 방카톡 이용 중지**(보호자 계정에 표시)는 이번 SQL 에 넣지 않음 — 필요하면 결정 후 추가.
- 개인정보(주민번호·계좌 등)를 보호자가 쓴 경우도 [가리기]로 처리 안내.
