# 직인사용대장 — 직인 증서 신청·결재·발급 (노미현 부장 요청 · 관장 결정)

- 요청: 노미현 부장(슬랙 #08, 2026-10-27), 관장 결정 반영 · 설계 2026-10-29
- 목적: 센터 직인이 들어가는 증서(수상확인증·수료증·표창장·상장·위촉장·기타)를 한 대장에서 신청 → 결재 → 발급
- SQL: `supabase/migrations/seal_register.sql`(작성만, 실행 전) · 브랜치 `seal-register`(main 기준)

## 0. 확정 사항(관장)

| 항목 | 내용 |
|---|---|
| 위치 | 공통 메뉴 "직인사용대장" — 모든 직원이 신청, 내 신청 목록·상태·출력 |
| 결재 | 부장 또는 관장 **1명** 승인으로 끝. 반려는 사유 필수 → 신청자가 고쳐서 다시 올림 |
| 알림 | 신청 시 부장·관장 슬랙 DM, 승인·반려 시 신청자 DM |
| 발급번호 | `제2026-01호` — 종류 상관없이 연도별 한 줄, 해 바뀌면 01부터. **승인하는 순간 DB에서** 부여 |
| 결재 전 PDF | "미리보기 · 직인 없음"으로만 |
| 시작 번호 | 관장이 설정 화면에서 연도별로 한 번 입력(올해 종이 발급분 이어받기) |
| 여러 명 | 한 신청에 대상자 여러 줄 → 승인 시 번호 차례로, PDF 한 파일(1인 1쪽) |
| 삭제 | 불가. 잘못 발급한 건은 "취소"(사유·취소자·시각), 번호는 결번. 재출력은 같은 번호, 기록 남김 |
| 결재 구조 | 공통 결재 표로 분리. 이번엔 직인대장만 사용, 공결·계약서 결재는 건드리지 않음 |

## 1. 지금 구조에서 가져다 쓰는 것(코드 실측)

- **센터장 직인 — 재사용 가능.** `lib/orgSeal.ts`의 기관 직인("동래구청소년센터장인")이 이미 재직·경력증명서, 강의확인증, 근로·연봉계약서에 쓰이고 있습니다.
  - 저장: 비공개 `hr-documents` 버킷, 경로는 `settings.organization_seal_path`(없으면 `org/center_seal.png`)
  - 읽기: `loadOrgSeal()` 한 줄. 등록·교체는 관장·부장 전용 `/hr/seal` 화면
  - 증명서 PDF(`lib/certificatePdf.ts`)가 이미 "동래구청소년센터장" 글자 끝에 직인을 겹쳐 찍습니다. 이번 양식도 같은 방법을 씁니다.
  - 등록된 직인이 빨간 사각 모양인지는 `/hr/seal` 화면에서 관장이 눈으로 확인해 주세요(코드로는 모양을 알 수 없음).
- **PDF**: 증명서와 같은 pdf-lib + 나눔고딕(글자 통째 넣기 — Vercel 글자 빠짐 방지).
- **슬랙 DM**: `lib/slack.ts`의 `sendSlackDMDetailed(이메일, 문구)` — 인사기록카드 이메일로 사람을 찾아 DM. 실패해도 결재는 그대로 진행(증명서와 같은 원칙).
- **관장·부장 찾기**: `drivers.rank`가 `관장`·`부장`인 재직 직원. 이메일은 `employee_profiles.email`.
- **번호 방식은 증명서와 따로**: 증명서는 `제2026년-10호`(번호 줄 `certificate_issues`), 이번은 `제2026-01호`로 형식도 줄도 다릅니다. 섞지 않습니다.
- **기관 대장(`/hr/org-records`)의 "수상"과 다름**: 그쪽은 센터가 *받은* 상 기록, 이번은 센터가 *내주는* 증서입니다. 연결하지 않습니다.

## 2. 표 구조(SQL 1~5)

| 표 | 한 줄이 뜻하는 것 | 주요 칸 |
|---|---|---|
| `approvals` | 결재 한 번(올릴 때마다 한 줄) | 종류(`seal_use`)·대상 id·차수·신청자·상태·결재자(이름·직급)·시각·반려 사유·**ERP 칸**(시스템·문서번호·상태·동기화 시각) |
| `seal_requests` | 신청 한 건 | 종류·제목·증서 날짜·사용 목적(대장용)·항목 틀·본문 틀·상태·현재 결재 |
| `seal_recipients` | 대상자 한 줄 = 발급번호 한 개 | 순서·성명(팀명)·○항목·본문·연도·번호·발급 시각·**snapshot**·취소(시각·취소자·사유) |
| `seal_number_counters` | 연도 하나 | 다음 번호·관장이 넣은 시작 번호·넣은 사람·시각 |
| `seal_print_logs` | 출력 한 번 | 뽑은 줄들·재출력 여부·출력자·시각 |

- 모든 표 RLS 켜고 정책 없음 → 브라우저 키로는 못 읽고 동업자씨 서버만 씁니다(기존 표들과 같음).
- **snapshot**: 승인 순간 번호·제목·항목·본문·날짜를 통째로 고정합니다. 재출력은 이것만으로 같은 PDF를 다시 만듭니다. PDF 파일 자체는 저장하지 않습니다.

## 3. 상태 흐름

```
작성 중(draft) ──올리기──▶ 결재 대기(pending) ──승인──▶ 발급(issued) ──(줄마다) 취소──▶ 결번
      ▲                        │  │
      │                        │  └──반려(사유 필수)──▶ 반려(rejected) ──고쳐서 올리기──▶ 결재 대기
      │                        └──신청자 회수──▶ 회수(withdrawn) ──고쳐서 올리기──▶ 결재 대기
      └ 한 번도 안 올린 작성 중 신청만 지울 수 있음
```

- 올릴 때마다 `approvals`에 새 줄(1차, 2차 …) — 반려 사유 이력이 그대로 남습니다.
- 결재 대기 중에는 신청 내용·대상자를 못 고칩니다(회수하면 고칠 수 있음).
- **DB가 직접 막는 것**(앱 실수가 있어도): 발급 뒤 내용·번호 변경, 발급 기록·결재·출력 기록 삭제, 취소 되돌리기, 승인 함수 밖에서 번호 붙이기, 본인 신청 결재, 반려·취소 사유 빈칸, 같은 신청 두 번 승인.

## 4. 발급번호 규칙

- 형식: `제{연도}-{두 자리}호` → `제2026-01호`, 100번부터는 `제2026-100호`.
- 연도: **승인 순간의 한국 시각** 기준(신청이 12월이어도 1월에 승인되면 새해 번호).
- 부여: `seal_approve_request` 함수 한 번에 처리합니다.
  1. 신청 줄을 잠금 → 부장·관장이 동시에 눌러도 한 명만 성공, 다른 한 명은 "이미 처리된 신청입니다."
  2. 그해 번호 줄을 잠금 → 다른 신청 승인은 순서대로 기다림 → **중복 없음**
  3. 대상자 순서대로 번호를 붙이고 다음 번호를 올림. 중간에 실패하면 번호까지 통째로 되돌아감 → **건너뜀 없음**
- 시작 번호: 관장이 연도별로 입력(`seal_set_start_no`). 예) 종이로 제2026-14호까지 냈으면 15 입력 → 첫 발급 제2026-15호. **그해 첫 발급 뒤에는 바꿀 수 없음**(번호가 꼬이지 않게).
- 취소한 번호는 결번으로 남고 다시 쓰지 않습니다.

## 5. 양식(PDF) — 수상확인증 실물 틀 그대로

A4 세로 한 쪽에 한 사람. 위에서 아래로:

1. 바깥 얇은 사각 테두리
2. 왼쪽 위 **"발급번호 : 제2026-01호"**(굵게)
3. 가운데 큰 제목 **"수 상 확 인 증"**(글자 사이 띄움, 굵게) — 증명서 PDF의 띄움 방식 재사용
4. ○ 항목(왼쪽 정렬, 이름 칸 너비를 맞춰 콜론 줄 맞춤)
   `○ 행 사 명 : …` / `○ 참가팀/명 : …` / `○ 참가일시 : 2026. 10. 17. (토)` / `○ 수상부문 : 대상`
5. 본문(가운데 정렬, 큰 글씨, 자동 줄바꿈)
6. 날짜(가운데, 굵게) "2026년 10월 17일" — 신청 때 정한 **증서 날짜**
7. 맨 아래 가운데 **"동래구청소년센터장"**(크게, 굵게) + 오른쪽 끝에 직인이 글자에 살짝 겹치게

**미리보기(결재 전)**: 번호 자리 "제2026-__호(승인 시 부여)", 직인 없음, 연한 회색 사선 글씨 "미리보기 · 직인 없음". 신청자·결재자 모두 볼 수 있음.

### 종류별 틀(신청 화면에서 고를 때 채워지는 기본값 — 직원이 모두 고칠 수 있음)

| 종류 | 제목 | ○ 항목 | 본문 틀 |
|---|---|---|---|
| 수상확인증 | 수상확인증 | 행 사 명 · 참가팀/명 · 참가일시 · 수상부문 | 위 사람은 {참가일시} {주최} {행사명}에서 {수상부문}을 수상하였음을 확인합니다. |
| 수료증 | 수료증 | 과 정 명 · 성 명 · 교육기간 | 위 사람은 동래구청소년센터에서 실시한 {과정명}을 성실히 이수하였기에 이 증서를 드립니다. |
| 위촉장 | 위촉장 | 성 명 · 위 촉 직 · 위촉기간 | 위 사람을 동래구청소년센터 {위촉직}(으)로 위촉합니다. |
| 표창장 | 표창장 | 성 명 · 소 속 | {공적 문구} 이에 표창합니다. |
| 상장 | 상장 | 성 명 · 소 속 | {공적 문구} 이에 이 상장을 드립니다. |
| 기타 | 직접 입력 | 직접(최대 8개) | 직접 |

- 항목마다 **"모두 같음"**(행사명·참가일시처럼 한 번만 입력) / **"사람마다"**(참가팀/명·수상부문) 구분 → 사람마다 칸은 대상자 표에 열로 나옵니다.
- 본문 틀의 {자리}는 대상자마다 채워 미리 보여 주고, 사람별로 문장을 따로 고칠 수도 있습니다.
- 수상확인증의 "{주최}"(부산광역시 동래구에서 주최하고 동래구청소년센터가 주관하는)는 행사마다 달라 직원이 씁니다.

## 9. 나중에 ERP 전자결재로 넘어갈 때

지금 구조는 "결재를 올리고 → 누가 결정하고 → 결정 결과를 DB 함수 하나로 반영"으로 나뉘어 있어, **결정을 누가 내리느냐만 바꾸면** 됩니다.

1. **올리기**: `seal_submit_request` 뒤에 ERP 상신 API를 부르고, 받은 문서번호를 `approvals.erp_system`·`erp_doc_no`에 저장(이미 칸 있음, 같은 문서번호 중복은 DB가 막음).
2. **결과 받기**: ERP 웹훅(또는 정해진 시간마다 조회)으로 승인·반려를 받아 **지금과 같은 함수** `seal_approve_request` / `seal_reject_request`를 부름. 결재자 이름·직급은 ERP 값. → 발급번호는 계속 우리 DB에서 승인 순간 붙음(번호 규칙 변화 없음).
3. **앱 버튼**: `erp_doc_no`가 있는 결재는 동업자씨 승인·반려 버튼을 숨기고 "ERP 결재 중(문서번호 …)"만 표시 → 이중 결재 방지.
4. **여러 단계 결재선**(기안→검토→결재)이 필요해지면 `approval_steps`(결재 id·차례·결재자·상태·시각) 표를 더하고, `approvals`는 최종 결과 요약으로 그대로 둠.
5. **다른 결재 옮기기**: 공결·계약서도 `doc_kind`만 늘려 같은 표로 옮길 수 있음. 각 기능의 기존 상태 칸을 옮기는 일은 그때 기능별로 따로 합니다(이번엔 손대지 않음).
6. ERP가 꺼져 있을 때를 대비해 "앱 결재로 되돌리기" 스위치(설정 표 키 하나)를 둡니다.

## 10. 순서(코드 작업 때)

1. SQL 실행(관장 확인 후 Claude가 MCP로) → `scripts/mobileCheck/db-schema.json`에 표 추가
2. `lib/approvals.ts`(공통 결재 읽기), `lib/sealRegister.ts`(종류별 틀·번호 표기·타입), `lib/sealRegisterServer.ts`(권한·조회·함수 호출·DM)
3. `lib/sealCertPdf.ts`(양식·미리보기·1인 1쪽) — 실물 수상확인증과 나란히 놓고 맞춤
4. 화면 4개 + 메뉴·배지
5. 시험: 권한(남의 신청 보기·결재 불가, 본인 결재 불가), 번호(동시 승인 흉내·결번·해 넘김·시작 번호), PDF 글자 넘침(긴 행사명·팀명·100명), 폰 화면 넘침·44px, tsc·린트

**이번에 해 둔 시험**: SQL을 내 PC의 임시 Postgres(PGlite)에서 두 번 실행(멱등 확인) + 시나리오 27개 통과 — 시작 번호 15 → 15·16·17 차례, 두 번째 승인 거절, 본인 결재 거절, 반려 → 수정 → 2차 승인(1차 반려 이력 남음), 취소 → 16 결번·다음 19, 발급 뒤 수정·삭제·시작 번호 변경 거절, 100번 → `제2026-100호`. 운영 DB에는 실행하지 않았습니다. 진짜 동시 접속은 PGlite로 흉내 낼 수 없어, 잠금 방식(4장)으로 보장합니다.

## 11. 결정 필요 항목

1. **증서 날짜**: 신청자가 정하는 날짜(기본값: 수상확인증은 행사일, 나머지는 오늘)로 할지, 무조건 승인일로 할지 — 추천: 신청자가 정함(실물처럼 행사 당일 날짜)
2. **전체 대장 보기 범위**: 관장·부장만 / 모든 직원 — 추천: 관장·부장만(청소년 이름이 들어감)
3. **발급 취소 권한**: 관장·부장만 / 신청자도 — 추천: 관장·부장만(신청자는 취소 요청을 반려 사유처럼 적어서)
4. **결재 대기 중 회수 허용**: 추천: 허용(고칠 일이 생기면 회수 → 고쳐서 다시 올리기)
5. **한 신청 최대 인원**: SQL은 200명까지 — 그대로 둘지
6. **시작 번호 잠금**: 그해 첫 발급 뒤 못 바꾸게(추천) / 언제든 올리기만 가능
7. **직인 모양 확인**: `/hr/seal`에 등록된 직인이 이 양식의 "빨간 사각 직인"과 같은 것인지 관장 확인
