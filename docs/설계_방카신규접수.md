# 동래방카 신규 청소년 온라인 접수(모집) 설계 · 2026-11-03

매년 같은 화면을 다시 쓰도록 **모집 회차(bk_recruitments)** 단위로 만듭니다.

| 쪽 | 저장소 | 화면 |
|---|---|---|
| 보호자(로그인 없음) | 동래방카 `dongrae-bangka` | `/apply` 신청, `/apply/recommend/[token]` 추천서 |
| 직원(방과후 직무 + M0) | 동업자씨 `dongrae-business-trip` | `/bangka/enroll` 회차·접수 목록·상세·합격 처리·엑셀 |
| DB | 동업자씨 `supabase/migrations/bk_enroll_apply.sql` | 관장 쪽에서 적용 |

공통 규칙(유형·서류·동의 키·입력값 모양)은 **동래방카 `lib/enroll.ts` = 동업자씨 `lib/bangkaEnroll.ts`** (같은 파일, 키를 바꾸면 두 곳 함께).

## 1. 표

| 표 | 내용 |
|---|---|
| `bk_recruitments` | 회차. status `draft 준비 / open 접수중 / closed 마감 / ended 종료`. `shuttle_stops` jsonb `[{seq,time,place}]`, 보관기간 `retention_accepted_years`·`retention_rejected_months`, `consent_version`, 접수번호 일련번호 `app_seq` |
| `bk_applications` | 신청서. `guardian_phone`(인증 번호, 숫자만)이 주인. 입력 전체 `data`, 민감정보 `sensitive`, 목록용 칸(youth_name 등), `fix_items`·`fix_reason`, 합격 후 `student_id`·`guardian_id`, `retention_until`·`purged_at` |
| `bk_application_files` | 서류 파일. `doc_kind`, `status uploaded/confirmed/needs_fix`, `fix_reason`, `rrn_masked_checked`, `checked_by/at`, `purged_at` |
| `bk_application_recommendations` | 추천서. 토큰은 sha256 해시만, 14일. 추천자가 쓴 칸 + 서명 |
| `bk_application_otps` | 인증번호 해시, 5분, 5회 실패 → 10분 잠금, 번호당 하루 10회 |
| `bk_application_access_logs` | 누가·언제·무엇을(파일 열람·다운로드·민감정보 열람·상태 변경·보완요청·합격·엑셀·보관 삭제) |
| `consent_records` | **OS 공용 동의 기록표**. 철회는 새 행(agreed=false). 가장 최근 행이 현재 상태 |
| `bk_students` + 칸 | `gender, return_method, return_note, shuttle_stop, allergy_info, application_id` |

모든 표 RLS on, 정책 0개(service_role 전용). 버킷 `bk-applications` 비공개, 1장 10MB, JPG·PNG·WebP·PDF.

## 2. 신청서 상태 흐름

```
draft(작성중) ──제출──▶ submitted(제출)
submitted ──직원: 서류 보완요청──▶ needs_fix(보완요청) ──보호자 다시 제출──▶ submitted
submitted ──직원: 서류 전부 확인──▶ docs_ok(서류확인)
submitted/docs_ok ──직원 결정──▶ accepted(합격) / waitlisted(대기) / rejected(불합격)
waitlisted ──▶ accepted (빈자리)
```

- 제출하면 보호자는 고칠 수 없음. `needs_fix` 일 때 `fix_items` 에 든 항목만 다시 열림.
- `fix_items` 키: `youth`, `photo`, `guardian`, `priority`, `consent`, `extra`, `recommend`, `doc:<doc_kind>`.
- 서류 파일의 [보완요청(사유)] → 그 파일 `status=needs_fix` + 신청서 `fix_items` 에 `doc:<kind>` 추가 + `status=needs_fix`. 보호자가 다시 제출하면 `fix_items=[]`, `status=submitted`, `resubmitted_at`.
- 보완요청 문자: `[동래구청소년센터] {청소년}의 방과후아카데미 신청서에 보완이 필요합니다. 사유: {사유} 고쳐 주세요: {BANGKA_BASE_URL}/apply`

## 3. 보호자 인증·세션(동래방카)

- 인증번호 6자리, `code_hash = sha256(phone:code:SESSION_SECRET)`. 5분 유효. 틀리면 `attempts+1`, 5회째 `locked_until = now()+10분`.
- 발송 한도: 번호당 한국 날짜 하루 10회(`bk_application_otps` 행 수로 셈). IP 당 시간 30회.
- 성공하면 서명 쿠키 `bangka_apply`(HS256, SESSION_SECRET, `aud=apply`, sub=번호) 24시간. 기존 보호자 로그인 쿠키(`bangka_session`)와 별개.
- 문자: 동래방카 서버 → sms-relay `POST /send` (`SMS_RELAY_URL`, `SMS_RELAY_KEY`), 발신번호 `0519880924`.
  키가 없고 개발 모드(`NODE_ENV !== 'production'`)면 화면에 인증번호를 보여 줌. 운영에서는 절대 표시하지 않음(키 없으면 503).

## 4. 우선지원 유형 · 서류 칸

`lib/enroll.ts` 의 `PRIORITY_TYPES`, `DOC_KINDS`. 공통 2종(`resident_register` 주민등록등본, `family_relation` 가족관계증명서) + 고른 유형의 칸만.
`disability_doc` 은 `sensitive: true` → 직원 화면에서 [민감정보 보기] 뒤에서만 열람.
청소년 사진은 `bk_applications.photo_path` (doc_kind 아님). 서명은 `guardian_signature_path`·`youth_signature_path`.

## 5. 입력값 모양

```ts
data = {
  youth:   { name, gender:'M'|'F', birth:'YYYY-MM-DD', zip, addr1, addr2, tel, mobile, email, school, grade, class_no, teacher, motive },
  guardian:{ name, relation:'legal'|'proxy', email },        // 휴대전화 = guardian_phone(인증 번호로 고정)
  priority:[ 'low_income', ... ],
  consent: { pledge:[true×5], answers:{ privacy_required, sensitive_medical_disability, optional_email, third_party, attendance : boolean } },
  ret:     { method:'shuttle'|'guardian'|'alone'|'other', other, stop_seq }   // stop_seq = 회차 shuttle_stops 의 seq
}
sensitive = { allergy: { has, foods:[1..19], other, symptoms:['skin',...], treated, self_aware } }
```

## 6. 동의 기록(consent_records)

제출할 때 한 번에 기록(subject_type=`bk_application`, subject_id=신청서 id, doc_version=회차 consent_version, ip·user_agent):

| consent_key | person_role | 내용 |
|---|---|---|
| `guardian_pledge` | guardian | 보호자 동의서 5개 항목 전부 |
| `privacy_required` | guardian | 개인정보 수집·이용(필수) |
| `sensitive_medical_disability` | guardian | 민감정보(필수) |
| `optional_email` | guardian | 선택정보(이메일) |
| `third_party` | guardian | 제3자 제공(필수) |
| `attendance` | guardian | 출석률 유지 |
| `youth_signature` | youth | 청소년이 서명했을 때만 |
| `recommender_privacy` | recommender | 추천서 제출 시(추천자 개인정보) |

보완요청으로 `consent` 를 다시 열어 바꾸면 다시 제출할 때 바뀐 항목만 새 행.

## 7. 합격 처리(동업자씨)

1. 반(이음/지음) 고르기 — `bk_students.class_code` 필수.
2. `bk_students` 새로: name, school, grade, school_class(=class_no), class_code, birth_date, gender, enrolled_on(오늘 또는 지정), return_method, return_note, shuttle_stop(회차 stops 에서 seq 로 찾은 값), allergy_info(sensitive.allergy), application_id.
3. 보호자: `bk_guardians.phone = guardian_phone` 이 이미 있으면 그 보호자에 연결만(상태 그대로). 없으면 `status=invited`, 초대 토큰 발급(기존 reissue 와 같은 규칙, 14일).
4. `bk_guardian_students` (is_primary=true) 연결.
5. 새 초대가 생긴 보호자에게 초대 문자(기존 `bkInviteMessage` 문구), 이미 쓰는 보호자에게는 "자녀가 추가되었습니다" 문자.
6. 신청서 `status=accepted, decided_at/by, student_id, guardian_id, retention_until = 그해 12/31 23:59:59 KST + N년`.
7. 기록: access_logs `accept`.

대기·불합격: `retention_until = now() + N개월`. 회차를 `ended` 로 바꾸면 아직 결정 안 된 신청서(작성중 포함)도 `now() + N개월`.

## 8. 보관기간 Cron(동업자씨)

`/api/cron/bk-enroll-purge` 매일(CRON_SECRET). `retention_until < now() and purged_at is null` →
증빙 파일(bk_application_files) Storage 삭제 + `purged_at`, `sensitive = null`, 추천서 서명 삭제.
불합격·대기·미결정이면 사진·서명도 삭제(`photo_path` 등 null). access_logs `purge`(actor_type=system).

## 9. 보안

- 직원 파일 열람: 서버가 5분 서명 URL 발급 후 redirect, 매번 access_logs. 공개 URL 없음.
- 보호자 파일 업로드: 서버가 경로를 정해 **1회용 서명 업로드 URL** 발급 → 브라우저가 그 URL 로 PUT → 서버가 내용(앞 바이트)·크기 확인 후 기록. (Vercel 요청 4.5MB 제한 때문. supabase-js·키는 브라우저에 없음.)
- 사진·서류 이미지는 업로드 전 브라우저에서 줄이고 다시 그려(EXIF·위치정보 제거) JPEG 로.
